# Deploying AUTHENTIQ for free (Render + Vercel)

Target stack:

| Piece | Host | Plan |
| --- | --- | --- |
| React/Vite frontend | Vercel | Hobby (free) |
| FastAPI backend | Render Web Service | Free |
| PostgreSQL | Neon (or Supabase) | Free |
| Ledger | built-in simulation file | — |

Everything below costs **$0**. The trade-offs of the free tiers are listed in
[Known free-tier limitations](#known-free-tier-limitations) — read that section
before treating the deployment as "production".

---

## 0. Prerequisites

- Repo pushed to GitHub (`rakshak2005/authentiq`, branch `main`).
- Accounts: [Render](https://dashboard.render.com/register),
  [Vercel](https://vercel.com/signup), [Neon](https://neon.tech).
- Generate the app secret locally:

  ```powershell
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```

---

## 1. Create the free PostgreSQL database (Neon)

Render's own free Postgres is **deleted 30 days after creation**, so use Neon
instead.

1. Neon dashboard → **New Project** → name `authentiq`, pick the region closest
   to your Render region (Singapore → `ap-southeast-1`).
2. Copy the **connection string** (pooled or direct). It looks like:

   ```
   postgresql://neondb_owner:xxxx@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/authentiq?sslmode=require
   ```

3. Keep it for step 2. The backend normalises `postgres://` and
   `postgresql://` to the `psycopg` driver automatically, so no edit needed.
4. Tables are created automatically on first boot (`init_db()` runs
   `create_all` + `alembic upgrade head`).

> Supabase works the same way: use the **session/direct** connection string
> (port 5432) and append `?sslmode=require`.

## 2. Deploy the backend on Render

### Option A — Blueprint (uses the committed `render.yaml`)

1. Render Dashboard → **New → Blueprint** → connect the GitHub repo.
2. Render reads `render.yaml` and shows one web service, `authentiq-api`.
3. Fill the prompted (`sync: false`) variables:

   | Variable | Value |
   | --- | --- |
   | `AUTHENTIQ_DATABASE_URL` | the Neon URL from step 1 |
   | `AUTHENTIQ_CORS_ORIGINS` | `https://<your-app>.vercel.app` |
   | `AUTHENTIQ_PUBLIC_APP_URL` | `https://<your-app>.vercel.app` |
   | `AUTHENTIQ_API_PUBLIC_URL` | `https://authentiq-api.onrender.com` |

   `AUTHENTIQ_SECRET_KEY` is generated by Render. `PYTHON_VERSION` is pinned to
   `3.12.7` because Render's new default (3.14) has no wheels for `web3`,
   `psycopg[binary]` and `argon2-cffi`.
4. **Apply**. First build takes ~3–6 min (installs `web3`, `psycopg`, etc.).
5. Wait for `Live`, then check:

   ```
   https://authentiq-api.onrender.com/api/health
   ```

   Expected: `{"status":"ok", ... "environment":"production" ...}`.

### Option B — Manual web service (same result)

| Field | Value |
| --- | --- |
| Language | Python 3 |
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/health` |
| Instance Type | Free |

Then add the same env vars under **Environment** (at minimum:
`AUTHENTIQ_ENVIRONMENT=production`, `AUTHENTIQ_SECRET_KEY`,
`AUTHENTIQ_DATABASE_URL`, `AUTHENTIQ_DEMO_MODE=false`,
`AUTHENTIQ_CORS_ORIGINS`, `AUTHENTIQ_PUBLIC_APP_URL`,
`AUTHENTIQ_API_PUBLIC_URL`, `PYTHON_VERSION=3.12.7`).

> The `startCommand` **must** bind to `$PORT` (Render defaults to `10000`).
> The repo `Dockerfile` hardcodes `8000`, so prefer the native Python runtime
> above. If you deploy with Docker instead, set
> `dockerCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT`.

### Required production env vars (why)

| Variable | Why |
| --- | --- |
| `AUTHENTIQ_ENVIRONMENT=production` | enables HSTS; **rejects** the default dev secret and `DEMO_MODE=true` |
| `AUTHENTIQ_SECRET_KEY` | JWT signing; must be ≥ 32 chars and not the default |
| `AUTHENTIQ_DATABASE_URL` | Postgres; otherwise SQLite inside the ephemeral disk |
| `AUTHENTIQ_CORS_ORIGINS` | browser calls from the Vercel origin are blocked without it |
| `AUTHENTIQ_PUBLIC_APP_URL` | links in the UI / share flows |
| `AUTHENTIQ_API_PUBLIC_URL` | public API URL used in responses/links |
| `AUTHENTIQ_DEMO_MODE=false` | required when `ENVIRONMENT=production` |

## 3. Deploy the frontend on Vercel

1. Vercel → **Add New → Project** → import the same GitHub repo.
2. Configure:
   - **Root Directory**: `frontend`
   - **Framework Preset**: Vite (auto-detected)
   - **Build Command**: `npm run build` (from `frontend/vercel.json`)
   - **Output Directory**: `dist`
   - **Install Command**: `npm ci`
3. **Environment Variables** (Production + Preview):

   | Name | Value |
   | --- | --- |
   | `VITE_API_URL` | `https://authentiq-api.onrender.com/api` |

   Vite inlines this at **build time** — after changing it you must redeploy.
4. **Deploy**. You get `https://authentiq-xxxx.vercel.app`.
5. SPA deep links (`/dashboard`, `/verify/...`) are handled by the rewrite in
   `frontend/vercel.json`; without it Vercel returns 404 on refresh.

---

## 4. Close the loop

1. Copy the final Vercel URL.
2. Render → `authentiq-api` → **Environment** → update
   `AUTHENTIQ_CORS_ORIGINS`, `AUTHENTIQ_PUBLIC_APP_URL`
   (comma-separated list for multiple origins) → **Save** (auto-redeploys).
3. Open the Vercel URL, register a user, upload a small file, register it, and
   run a verification. Watch the Render logs for errors.

### Smoke test checklist

```
GET  /api/health                      -> 200, environment=production
POST /api/auth/register               -> 201
POST /api/auth/login                  -> 200 + token
POST /api/uploads/initiate            -> 201
POST /api/uploads/{id}/chunks         -> 200
GET  /api/ledger/status               -> mode=simulation, tamper_detected=false
```

Browser devtools: no CORS errors, `Authorization: Bearer ...` present.

## Known free-tier limitations

These are platform limits, not bugs in the app:

1. **Ephemeral filesystem (biggest issue).** Render free instances have no
   persistent disk, and the filesystem is wiped on every deploy, restart and
   idle spin-down (15 min without traffic). This app stores on disk:
   - uploaded encrypted originals/chunks (`storage/uploads/`),
   - dispute evidence (`storage/evidence/`),
   - the simulation ledger (`storage/ledger.jsonl`).

   After a wipe, Postgres rows survive but files and the local ledger do not —
   the ledger restarts at genesis, so `ledger/status` shows `tamper_detected`
   and downloads of old files 404. Mitigations, cheapest first:
   - use **Polygon Amoy** (`AUTHENTIQ_LEDGER_MODE=polygon` + RPC/private
     key/contract from `blockchain/`) so ledger records live on-chain;
   - attach a Render **persistent disk** (paid instance, ~$1–7/mo);
   - move file storage to Cloudflare R2 / Supabase Storage (requires adding an
     S3 storage adapter in `backend/app/storage/`).
2. **Cold starts.** Free services spin down after 15 idle minutes; the next
   request waits ~50–60 s. A free cron pinger (e.g. cron-job.org, every 10 min)
   keeps it warm — 24/7 usage is 744 h/month against the 750 h free allowance.
3. **512 MB RAM / 0.1 CPU.** Measured import footprint of this app is ~147 MB,
   so it fits, but concurrent 200 MB uploads are slow. Consider
   `AUTHENTIQ_MAX_FILE_SIZE_MB=50` for the free tier.
4. **750 free instance hours + 100 GB bandwidth per month** per workspace.
   Exceeding hours suspends free services until the next month.
5. **Free Render Postgres expires after 30 days** — that is why step 1 uses
   Neon. (Neon's free tier is ~0.5 GB with auto-suspend; check current limits.)
6. **CORS is an exact-match list.** Vercel *preview* deployments get random
   URLs and will be blocked until you add them to `AUTHENTIQ_CORS_ORIGINS`
   (or add `allow_origin_regex` support in `backend/app/main.py`). Production
   domain and custom domains are fine.
7. **No backups** on free tiers. `pg_dump` the Neon database before demos.
8. **`web3` is imported eagerly** in `backend/app/ledger/blockchain.py`. It
   costs build time and ~40 MB RAM even in simulation mode. Making that import
   lazy would speed up free-tier boots.

## Alternatives if you outgrow the free tier

| Need | Suggestion | Free? |
| --- | --- | --- |
| More RAM / no spin-down | Render Starter (`0.5c-512mb`) or `1c-2g` | from ~$7/mo |
| Persistent files | Render Disk (paid instance only) | from ~$1/mo |
| Persistent files, free | Cloudflare R2 (10 GB, free egress) or Supabase Storage (1 GB) + small S3 adapter | yes |
| Durable ledger | Polygon Amoy testnet (free test MATIC) | yes |
| Backend with more RAM, free | Hugging Face Spaces (Docker, 2 vCPU / 16 GB, public repo caveat) | yes |
| Backend with card on file | Google Cloud Run (generous free allowance, scales to zero) | yes* |
| Full control | Oracle Cloud Always Free VM (ARM, 24 GB) — you manage nginx/systemd | yes |
| Managed Postgres | Neon, Supabase, Aiven | yes (small) |

\* requires a billing account; usage inside the free allowance is not charged.
